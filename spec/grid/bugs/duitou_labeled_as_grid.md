# 堆头（促销堆叠陈列）被标成棚格

## 现象
- 标注回收里出现把"堆头/促销堆叠陈列"当棚格标注的框；
- 反过来，测试集重标时标注人员又把某些堆头图**整图清空**（导出包因此没有对应标签文件）；
- 模型在堆头图上普遍会检出 4–23 个框，**用"模型检出"无法区分堆头与棚格**。

## 根因
堆头在图像上与棚格形态接近（成排商品 + 横向分层），标注规则只写了"棚格=陈列单元"，
没有把堆头/海报/样品展示列为"不标注场景"；不同标注人员理解不一致。

## 证据
- 测试集回流标签比预标注少 2 个文件，对应图片预标注分别有 20 / 15 框，而 4 个权重在该图上
  分别检出 10–23 框（均值 conf 0.68–0.83）；
- 业务确认这 4 张（`q0031…`、`q0048…`、`q0065…`、`q0181…`）是堆头后，从测试集删除；
- 另有 2 张（`q0065…`、`q0181…`）GT 有 3–4 框、模型检出 4–5 框，最终也被业务确认为堆头。

## 处置
- 确认后的堆头图从**所有位置**同步删除：原图源、合并集 test、各测试集视图（grid2000/combined 等）、
  评测清单；删除用"移动到 `_archive_*`"而非硬删，附 MAPPING 记录；
- 同步清理因此产生的断链（混合视图里的软链）；
- 删除后测试集规模变化（6 来源 1126→1122、grid2000 168→166），相关指标全部重跑。

## 预防
- 规则库补"不标注场景"：堆头 / 海报 / 样品展示 / 人物 / 透视远端货架，作为 hard-negative 单独统计；
- 建任务前先跑 Step0–3 预筛，把可疑场景先剔除再交给标注人员；
- 判定堆头必须人工看图确认，禁止用"模型检出/置信度"作为依据。
