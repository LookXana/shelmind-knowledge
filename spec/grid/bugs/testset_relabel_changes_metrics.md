# 测试集标签清洗/换版会让所有模型指标整体变化

## 现象
把固定测试集（6 来源 1126 张）的标签换成标注人员回流清洗后的版本后，
**四个模型（v2.2.9 初值 / mix6 / mix7 / mix6_ft）在同一批预测上 F1 全部下降 0.011~0.013**，
P、R 同步下降；其中 grid3345 降幅最大（−0.021~−0.024），grid1276c 反而略升（+0.001~+0.002）。

## 根因
旧标签偏"松"：框边界不够贴合真实陈列单元，模型的框"糊"上去也能在 IoU 0.5 下匹配；
清洗后框更准更紧，原先的边缘匹配不再成立 → 同一批预测的 TP 减少、FP/FN 增加。
即：**指标变化来自 GT 口径变化，不是模型变化**。

## 证据
- 同一批预测、只替换 GT 目录重判（纯 CPU，无需重新推理）：
  v2.2.9 0.9301→0.9186、mix6 0.9385→0.9258、mix7 0.9378→0.9261、mix6_ft 0.9397→0.9285；
- 模型排名不变（mix6_ft > mix7 ≈ mix6 > v2.2.9），但绝对值和彼此差距都变化；
- 清洗前后框数几乎不变（23426→23428），说明差异在"位置"而不是"数量"。

## 处置
- 新标签作为**唯一测试口径**，旧数字一律标注"旧标签口径"并停止对外引用；
- 换标签后对所有对比模型重跑（本次复用已存预测 + 重判，成本大幅低于重新推理）；
- 报告头部必须写清：测试集版本 + 标签版本 + conf/NMS/match IoU/imgsz。

## 预防
- 测试集标签变更视同**测试集变更**，走"冻结/解冻"流程：变更记录 + 全模型重跑 + 报告更新；
- 保留一份旧标签副本（如 `<dataset>/old_labels/`），便于做"口径变更影响"对比；
- 结论对外发布前，先确认引用的数字属于当前标签口径。
