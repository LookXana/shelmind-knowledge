# 隔离/移动源文件后标签软链断链，审计脚本看不出来

## 现象
清理"孤儿标签"时把 1314 个无前缀标签移入隔离目录后，视图里 1314 个带前缀标签软链全部变成**断链**；
但当时的对账统计仍显示"8733 图 / 8733 标签"，看起来一切正常。

## 根因
- 软链指向同目录的另一份标签文件，移动目标后链断；
- 审计脚本用的是"文件名计数"（`glob("*.txt")` 数量）而不是"可解析到的真实文件"，断链被计入；
- `Path.exists()` 会跟随软链，断链返回 False，但只在**逐文件检查**时才暴露。

## 证据
- `find -L <labels_dir> -maxdepth 1 -type l | wc -l` = 1314（全部断链）；
- 同目录 `find -L ... -type f` 只有 7419 个可用文件；
- 抽样 `head` 断链文件内容为空（读取失败）。

## 处置
- 断链标签按"从隔离区重建真实文件"的方式恢复（copyfile 而非软链）；
- 视图一致性检查改为三重：**文件数 + 断链数 + 空标签数**，并纳入开训门禁；
- 清理脚本改为"移动前先确认视图不依赖该文件"。

## 预防
- 任何隔离/移动动作后跑 `find -L <dir> -type l` 断链检查；
- 审计脚本必须区分"存在"与"可解析"：`p.is_symlink() and not p.exists()`；
- 跨目录引用优先用真实文件（复制），少用相对软链。
