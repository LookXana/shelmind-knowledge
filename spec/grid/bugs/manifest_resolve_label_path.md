# 训练清单用 Path.resolve() 导致标签路径解析失败

## 现象
混合采样训练（mix7）第一遍结果异常：沙河域 F1 崩到 0.09–0.54，而同批权重在 grid3345 / grid2000 上正常（0.964 / 0.889）。
训练日志无报错，数据"看着"齐全。

## 根因
生成 epoch 清单时用 `Path.resolve()` 把视图软链解析成**图源真实路径**：
`<GRID_SERVER_LJH>/data/images_tianhong0826_0827_20260910/<stem>.jpg`。
该目录名是 `images_xxx`，**不含 `/images/` 段**，Ultralytics 的 `img2label_paths()` 用
`x.rsplit("/images/", 1)` 找不到分隔符 → 原样把后缀换成 `.txt` → 指向不存在的标签。
Ultralytics 对"标签缺失"不是丢弃样本，而是置空框后**仍保留该图**（`verify_image_label` 返回 `nm=1`，`lb` 为空），
于是 2000/14000 条样本被当成**无目标背景**训练 —— 模型学会"这些场景不要检框"。

## 证据
- 清单 14000 行中 2000 行（沙河新批）解析出的标签路径全部不存在（只读复现脚本 `verify_mix7_20260922.py`）；
- 同款 bug 也解释了标签软链"清单不引用"的情况：修好视图标签但清单仍指图源目录 → 等于没修；
- 修复后（清单改指视图路径）沙河合计 F1 从 0.3274 恢复到 0.9418。

## 处置
- 清单只写**视图路径**（`<dataset>/images/train/<name>.jpg`），禁止 `resolve()`；
- 生成后强制门禁：逐行解析标签路径，**缺标签 0 / 空标签 0 / 堆头 0 / 泄漏 0** 才允许开训；
- 旧清单留档 `.bak_*`，出问题可回滚。

## 预防
- 训练前必跑"按清单逐行解析标签"的门禁脚本，而不是只对账视图目录（images/ vs labels/）；
- 图源目录命名不要带 `images_` 前缀以外的花样，避免与 Ultralytics 的 `/images/` 约定冲突；
- 任何"移动/隔离标签"的动作之后重跑门禁（断链会让 `.exists()` 变假）。
